1

Fix the error and update the backend

5 min
  1. 1.1
    Delete the old Code.gs

    In your Apps Script project (script.google.com/home → Tuto Desk), point at Code.gs in the Files list and click its ⋮ menu, then Delete, then Delete forever.

    Do the same for index.html. The backend doesn't need it; that file lives on Netlify.

    Only appsscript.json is left in the Files list.

  2. 1.2
    Create a fresh Code.gs
    • Click the + next to Files, choose Script, type Code and press Enter.
    • The new file has a few lines of sample code. Click inside it, press Ctrl+A, then Delete.
    • On your Desktop, open the Tuto Desk folder. Right-click Code.gs, choose Open with → Notepad, then press Ctrl+A and Ctrl+C.
    • Back in Apps Script, click inside the empty file and press Ctrl+V, then Ctrl+S.

    The file ends at about line 808. Scroll to the bottom to check. The words const PROPS appear only once (press Ctrl+F and search to confirm). "Unsaved changes" at the top has gone.

  3. 1.3
    Run setup

    Choose setup in the function dropdown next to Debug and click ▷ Run. If Google asks for permission: click Review permissions, choose your Gmail, click Advanced, then Go to Tuto Desk (unsafe), tick Select all and click Allow.

    Done. Data sheet: https://docs.google.com/… in the Execution log. Copy that link; you'll need it in part 3.

  4. 1.4
    Publish the new version (same link)
    • Click Deploy, then Manage deployments.
    • Click the ✎ pencil (top right). Under Version, choose New version.
    • Click Deploy, then Done.

    Don't use New deployment. That creates a new link and the app would lose its connection.

2

Turn on "Continue with Google"

10 min, once

This lets teammates sign in with one tap. The same tap gives the app read-only access to their own calendar, so nobody has to connect anything. Do all of this signed in as veronica.singh2525@gmail.com.

  1. 2.1
    Create a Google Cloud project

    Open console.cloud.google.com/projectcreate. Set Project name to TUTO Desk and click Create. When the notification bell says it's ready, click Select project.

  2. 2.2
    Set up the sign-in screen

    Open Google Auth Platform (check TUTO Desk is the project shown at the top) and click Get started:

    • App information: App name TUTO Desk, User support email: your Gmail. Click Next.
    • Audience: choose External. Click Next.
    • Contact information: your Gmail. Click Next.
    • Tick the agreement, then click Continue and Create.
    • Click Branding on the left and fill in App domain. All three links are required before Google lets you publish:
      Application home pagehttps://tutodesk.netlify.app/about.html (the public page, not the sign-in screen)
      Application privacy policy linkhttps://tutodesk.netlify.app/privacy.html
      Application Terms of Service linkhttps://tutodesk.netlify.app/terms.html
    • Under Authorised domains, type tutodesk.netlify.app: just the domain, with no https:// and no /. Click Save.

    Upload the latest Tuto Desk folder to Netlify first (step 4.1), so the privacy and terms pages exist.

    "Invalid domain: must not specify the scheme" means you typed https://. Remove it and the trailing /.

  3. 2.2b
    If "Branding verification issues" appears

    Try this first (2 min): on the Branding page, clear the three App domain links (home page, privacy, terms). Keep tutodesk.netlify.app under Authorised domains. Click Save, then go to Audience → Publish app. Without these links, Google doesn't run the branding check, and the app works the same (users see a one-time "unverified app" notice).

    If Publish app is still greyed out, do the full fix:

    • Prove you own the site. Open Google Search Console (signed in as your Gmail) → Add property → the right-hand URL prefix box → https://tutodesk.netlify.app/ → Continue. Under HTML file, click the download button. Move the downloaded google….html file from Downloads into your Tuto Desk folder, upload the folder to Netlify again, then click Verify in Search Console.
    • Fill in the links using the table above. The home page must be /about.html, a public page that explains the app without a login. Click Save.
    • In the Branding verification issues panel, choose I have fixed the issues, then Proceed. Google re-checks, usually within a few days. Then Audience → Publish app.
  4. 2.3
    Enable the Calendar API

    Open Google Calendar API and click Enable.

  5. 2.4
    Allow read-only calendar access

    In Google Auth Platform, click Data access on the left, then Add or remove scopes. In the filter box, type calendar.readonly, tick the row …/auth/calendar.readonly, click Update, then Save at the bottom.

  6. 2.5
    Create the web client

    Click Clients on the left, then + Create client:

    • Application type: Web application. Name: TUTO Desk web.
    • Under Authorized JavaScript origins, click + Add URI and enter https://tutodesk.netlify.app, with no slash at the end.
    • Leave "Authorized redirect URIs" empty. Click Create.
    • A box shows the Client ID and Client secret. Copy both into a note now; the secret is shown only once. You can also click Download JSON.
  7. 2.6
    Publish the app

    Click Audience on the left, then Publish app, then Confirm.

    Publishing status: In production.

    Don't skip this. In "Testing" mode, Google cuts calendar access every 7 days and people would have to sign in again. You don't need to submit for verification, which only matters above 100 users. Teammates will see a one-time "unverified app" notice; the join page tells them what to tap.

  8. 2.7
    Give the IDs to the backend

    In Apps Script, go to Project Settings (gear) → Script Properties → Add script property, and add two rows:

    PropertyValue
    GOOGLE_CLIENT_IDthe Client ID (ends in .apps.googleusercontent.com)
    GOOGLE_CLIENT_SECRETthe Client secret (starts with GOCSPX-)

    Click Save script properties. No redeploy is needed.

5

Real WhatsApp delivery · when you're ready

Nudges already go to each person's number from the Team tab, but until a WhatsApp provider is connected they appear only under the bell, marked "Preview". To send real messages:

  1. Sign up with a WhatsApp provider. Interakt is the easiest in India. You'll need a number that isn't already on WhatsApp.
  2. Create a Utility template named tuto_desk_alert with the body TUTO Desk: {{1}}, then wait for approval (1–3 days).
  3. Add these Script Properties: WA_PROVIDER = interakt, INTERAKT_KEY = your API key, WA_TEMPLATE = tuto_desk_alert.
  4. In the app, go to Settings and tap Test nudge.

Teammates don't do anything for this either.
